1.1 C Programming Overview Module 1

What is C?

C is a general-purpose, procedural programming language developed by Dennis Ritchie at Bell Labs in 1972. It was originally designed for system programming, particularly for developing the UNIX operating system.

C is known for its efficiency, low-level memory access capabilities, and portability. It provides a foundation for many modern programming languages including C++, Java, C#, and Python.

Why Learn C?

Learning C programming offers several advantages:

  • Foundation: Understanding C helps you grasp fundamental programming concepts used in other languages.
  • Performance: C programs are fast and efficient, making it ideal for system-level programming.
  • Control: Direct access to memory through pointers gives you fine-grained control over system resources.
  • Portability: C code can be compiled and run on various platforms with minimal modifications.
  • Career: C is widely used in embedded systems, operating systems, and high-performance applications.

Key Features of C

  1. Simple & Efficient: C has a small set of keywords (32 in ANSI C) and straightforward syntax.
  2. Procedural Language: Programs are structured as procedures or functions that operate on data.
  3. Middle-Level Language: Combines features of both high-level and low-level languages, allowing system programming while maintaining readability.
  4. Pointers: Direct memory manipulation through pointers makes C powerful but requires careful handling.
  5. Rich Library: Standard library provides numerous built-in functions for common operations.
  6. Extensible: You can add your own functions to the C library.
Did You Know? C was originally developed to re-implement the UNIX operating system. Before C, UNIX was written in assembly language. The creation of C made UNIX portable across different hardware platforms, revolutionizing operating system development.
Quick Info: The Name "C"
C was named as a successor to the B programming language, which was developed by Ken Thompson. B itself was influenced by BCPL (Basic Combined Programming Language). The naming follows a simple alphabetical progression: BCPL → B → C!
Deep Dive: C's Influence on Modern Languages
The C Family Tree: C has influenced countless programming languages. Here's how:

Direct Descendants:
  • C++: Object-oriented extension of C
  • Objective-C: Object-oriented layer on C (used in iOS/macOS)
  • C#: Microsoft's modern take on C syntax
Syntax Influence:
  • Java: Borrowed C's syntax and control structures
  • JavaScript: Syntax inspired by C
  • PHP: Uses C-like syntax
  • Go: Modern language with C-inspired syntax
Even Python's reference implementation (CPython) is written in C!

Your First C Program

Let's start with the traditional "Hello, World!" program that demonstrates the basic structure of a C program: 

// File: hello.c
// This is a simple C program

#include <stdio.h>

int main() {
    printf("Hello, World!\n");
    return 0;
}

Breaking Down the Code

  • #include <stdio.h> — Preprocessor directive that includes the Standard Input/Output library header file.
  • int main() — The main function where program execution begins. int indicates it returns an integer value.
  • printf() — Library function to print formatted output to the console.
  • \n — Escape sequence for a newline character.
  • return 0; — Returns 0 to the operating system, indicating successful program execution.

1.2 History & Features Module 1

The Birth of C (1972)

C was created by Dennis Ritchie at Bell Laboratories between 1972 and 1973 to develop the UNIX operating system. Before C, UNIX was written in assembly language, making it difficult to port to different hardware platforms.

C was designed as a successor to the B language (created by Ken Thompson), which itself was derived from BCPL. The goal was to create a language that was:

  • Close to the hardware (like assembly)
  • Portable across different machines
  • Efficient and fast
  • Simple enough to be easily learned

Evolution Through Standards

C has evolved through several standardization efforts over the decades:

Year Standard Key Features
1978 K&R C First edition of "The C Programming Language" by Kernighan and Ritchie. De facto standard before official standardization.
1989 ANSI C (C89) First official standard. Added function prototypes, void pointers, standard library formalization.
1990 ISO C (C90) ISO adoption of ANSI C89 with minor modifications. Widely supported baseline.
1999 C99 Inline functions, variable-length arrays, // comments, long long, flexible array members, _Bool type.
2011 C11 Multithreading support, improved Unicode support, anonymous structures/unions, _Generic keyword, bounds-checking functions.
2017 C17 (C18) Bug fixes and clarifications to C11. No new features, mainly defect resolution.
2023 C23 Binary literals, typeof, improved attributes, #embed directive, enhanced type safety.
Quick Info: The K&R Book
"The C Programming Language" by Brian Kernighan and Dennis Ritchie (often called "K&R") is one of the most influential programming books ever written. First published in 1978, it defined C before any official standard existed. The book's second edition (1988) covers ANSI C and remains a classic reference today.

Core Features of C

1. Simplicity & Minimalism

C has only 32 keywords in ANSI C (44 in C23). This small keyword set makes the language easy to learn while remaining powerful through its standard library and user-defined functions.

2. Efficiency

C provides direct access to memory through pointers and allows low-level manipulation of data. Programs compiled in C run with minimal overhead, making it ideal for:

  • Operating systems (Linux, Windows kernel components)
  • Embedded systems (microcontrollers, IoT devices)
  • Game engines (performance-critical components)
  • Database systems (MySQL, PostgreSQL core)

3. Portability

C code can be compiled and run on virtually any platform with a C compiler. The same source code can work on:

  • Desktop systems (Windows, macOS, Linux)
  • Mobile devices (Android NDK, iOS)
  • Embedded systems (Arduino, Raspberry Pi)
  • Mainframes and supercomputers

4. Structured Programming

C supports structured programming with functions, loops, and conditional statements, promoting code organization and reusability.

5. Rich Standard Library

The C standard library provides functions for:

  • stdio.h - Input/output operations
  • stdlib.h - Memory allocation, conversions
  • string.h - String manipulation
  • math.h - Mathematical functions
  • time.h - Date and time functions
Deprecated Features Warning Some older C features are now deprecated or removed in modern standards:
  • gets() - Removed in C11 (use fgets() instead)
  • Implicit int - No longer allowed in C99+
  • K&R style function declarations - Use ANSI prototypes
Deep Dive: Why C Remains Relevant in 2025
Despite being over 50 years old, C remains one of the most widely used programming languages. Here's why:

1. Operating Systems: Linux kernel, Windows drivers, and macOS core components are written in C.

2. Performance Critical Applications: When every microsecond counts (high-frequency trading, real-time systems), C is the go-to choice.

3. Embedded Systems: With billions of IoT devices, C dominates embedded programming due to its small footprint and hardware control.

4. Foundation for Other Languages: Understanding C helps you understand how Python, Java, and JavaScript work under the hood.

5. Longevity: C code written 30 years ago can still compile and run today with minimal changes.
Try It Yourself: Check Your Compiler Version Open your terminal and run these commands to check which C standard your compiler supports: 
# GCC
gcc --version
gcc -dM -E - < /dev/null | grep __STDC_VERSION__

# Clang
clang --version
clang -dM -E - < /dev/null | grep __STDC_VERSION__
The __STDC_VERSION__ macro shows the standard:
  • 199901L = C99
  • 201112L = C11
  • 201710L = C17
  • 202311L = C23

1.3 Program Structure Module 1

Anatomy of a C Program

Every C program follows a specific structure. Understanding this structure is crucial for writing organized and maintainable code. 

/* 1. PREPROCESSOR DIRECTIVES */
#include <stdio.h>      // Standard I/O library
#include <stdlib.h>     // Standard library
#define PI 3.14159      // Macro definition
#define MAX(a,b) ((a) > (b) ? (a) : (b))

/* 2. GLOBAL DECLARATIONS */
int globalVar = 100;    // Global variable
const int DAYS = 7;     // Global constant

/* 3. FUNCTION PROTOTYPES */
void greet(void);
int add(int a, int b);

/* 4. MAIN FUNCTION */
int main() {
    // 4a. Local variable declarations
    int localVar = 50;
    
    // 4b. Statements and expressions
    printf("Global: %d, Local: %d\n", globalVar, localVar);
    greet();
    
    int sum = add(10, 20);
    printf("Sum: %d\n", sum);
    
    // 4c. Return statement
    return 0;  // Success
}

/* 5. FUNCTION DEFINITIONS */
void greet(void) {
    printf("Hello from greet function!\n");
}

int add(int a, int b) {
    return a + b;
}

Program Structure Breakdown

1. Preprocessor Directives

Lines starting with # are processed before compilation. Common directives include:

  • #include - Includes header files
  • #define - Defines macros and constants
  • #ifdef, #ifndef - Conditional compilation
  • #pragma - Compiler-specific instructions

2. Global Declarations

Variables and constants declared outside all functions. They have file scope and exist for the entire program lifetime.

Minimize Global Variables Excessive use of global variables can lead to:
  • Difficult debugging (any function can modify them)
  • Name conflicts in large projects
  • Reduced code reusability
Use static keyword to limit scope to current file.

3. Function Prototypes (Forward Declarations)

Declares functions before they're defined. This allows you to:

  • Call functions before their definition
  • Organize code with main() at the top
  • Enable compiler type checking

4. The main() Function

The entry point of every C program. Two standard forms:

// Form 1: No command-line arguments
int main(void) {
    // code
    return 0;
}

// Form 2: With command-line arguments
int main(int argc, char *argv[]) {
    // argc: argument count
    // argv: argument vector (array of strings)
    return 0;
}

5. Function Definitions

Actual implementation of functions. Each function should:

  • Have a single, well-defined purpose
  • Use descriptive names (verbs for actions)
  • Keep length reasonable (typically < 50 lines)
  • Document complex logic with comments

Quick Info: Why main() Returns int?
The main() function returns an integer to the operating system to indicate the program's exit status:
  • 0 = Success (standard convention)
  • Non-zero = Error (different values can indicate different errors)
In Unix/Linux, you can check the exit status of the last command with echo $?. This is useful for shell scripts and automation.
Try It Yourself: Multi-File Program Create a program split across multiple files:

math_ops.h (Header file): 
#ifndef MATH_OPS_H
#define MATH_OPS_H

int add(int a, int b);
int multiply(int a, int b);

#endif
math_ops.c (Implementation): 
#include "math_ops.h"

int add(int a, int b) {
    return a + b;
}

int multiply(int a, int b) {
    return a * b;
}
main.c (Main program): 
#include <stdio.h>
#include "math_ops.h"

int main() {
    printf("5 + 3 = %d\n", add(5, 3));
    printf("5 * 3 = %d\n", multiply(5, 3));
    return 0;
}
Compile with: gcc main.c math_ops.c -o program

Stage 1: Preprocessing

The preprocessor handles all directives starting with #:

  • Includes header files (#include)
  • Expands macros (#define)
  • Removes comments
  • Handles conditional compilation (#ifdef, #ifndef) 
# View preprocessed output
gcc -E program.c -o program.i
# or
cpp program.c > program.i

Stage 2: Compilation

The compiler translates preprocessed C code into assembly language specific to your CPU architecture (x86, ARM, etc.). 

# Generate assembly code
gcc -S program.c -o program.s

Stage 3: Assembly

The assembler converts assembly code into machine code (binary), creating an object file (.o or .obj). 

# Create object file
gcc -c program.c -o program.o

Stage 4: Linking

The linker combines your object files with library code (like printf from the C standard library) to create the final executable. 

# Link and create executable
gcc program.o -o program

# Or do all stages at once
gcc program.c -o program

Common GCC Compiler Flags

Flag Purpose Example
-o Specify output filename gcc main.c -o myprogram
-Wall Enable all warnings gcc -Wall main.c
-Werror Treat warnings as errors gcc -Wall -Werror main.c
-g Include debugging information gcc -g main.c -o debug
-O0, -O1, -O2, -O3 Optimization levels (0=none, 3=max) gcc -O2 main.c -o fast
-std=c99 Specify C standard gcc -std=c11 main.c
-I Add include directory gcc -I./include main.c
-L Add library directory gcc -L./lib main.c
-l Link with library gcc main.c -lm (math lib)
Common Compilation Errors
  • Undefined reference: Missing function definition or library
  • Implicit declaration: Missing function prototype or header
  • Multiple definition: Same function defined in multiple files
  • Cannot find -l[library]: Library not installed or wrong path
Always compile with -Wall to catch potential issues early!
Deep Dive: Static vs Dynamic Linking
Static Linking: Library code is copied into your executable.
  • ✓ Executable runs standalone (no external dependencies)
  • ✓ Faster startup time
  • ✗ Larger executable size
  • ✗ Must recompile to update libraries

Dynamic Linking: Executable references shared libraries (.so, .dll).
  • ✓ Smaller executable size
  • ✓ Libraries can be updated independently
  • ✓ Multiple programs share same library in memory
  • ✗ Requires library files at runtime

Compile statically: gcc -static program.c -o program
Default is dynamic linking.
Try It Yourself: Explore Compilation Stages Create a simple program and examine each stage: 
// test.c
#include <stdio.h>
#define GREETING "Hello, World!"

int main() {
    printf("%s\n", GREETING);
    return 0;
}
Run these commands:
  1. gcc -E test.c -o test.i - View preprocessed code
  2. gcc -S test.c -o test.s - View assembly code
  3. gcc -c test.c -o test.o - Create object file
  4. gcc test.o -o test - Link to executable
  5. ./test - Run the program!
Open test.i and test.s to see what the compiler does!
